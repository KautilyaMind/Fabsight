# FabSight — Synthetic Semiconductor Process Intelligence Agent

FabSight is a portfolio and educational project for exploring how AI process
intelligence might be applied to semiconductor manufacturing. Version 0.1 builds
only the clean, relational data backbone needed for later learning exercises.

> **Data notice:** Everything generated by v0.1 is synthetic educational simulation
> data. It does not use or reproduce proprietary manufacturing data, equipment
> configurations, sensor definitions, recipes, products, alarms, or internal systems
> from a real semiconductor manufacturer.

## What v0.1 does

It creates a deterministic, simplified fab environment:

```text
Lots
 ↓
Wafers
 ↓
Process steps
 ↓
Tools
 ↓
Process events
```

It also creates generic fictional maintenance and alarm records linked to tools.
Every wafer follows seven broad educational stages: clean, deposition, lithography,
etch, implant, CMP, and inspection. These are conceptual abstractions, not recipes.

## What v0.1 does not do

- No proprietary manufacturing data or real product definitions
- No proprietary recipes, procedures, tool configurations, or alarm definitions
- No machine learning or causal defect simulation
- No wafer images or vision system
- No SECOM or WM-811K integration
- No LLM, agent, LangChain, or LangGraph
- No API, dashboard, or deployment framework

Those capabilities are deliberately reserved for separately scoped future versions.

## Setup

Python 3.11 or newer is recommended.

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

## Generate and validate the data

From the repository root, run:

```powershell
python scripts/generate_synthetic_fab.py
```

The command writes seven CSV files to `data/synthetic/`, prints row counts, and
automatically validates IDs, foreign keys, mandatory values, durations, and process
ordering. Generation uses the fixed seed in `src/fabsight/config.py`, so rerunning
with the same code and dependency versions produces the same CSV content.

To run validation separately:

```powershell
$env:PYTHONPATH = "src"
python -m fabsight.validation.validate_data
```

## Run the tests

```powershell
python -m pytest
```

The tests check file creation, unique IDs, foreign keys, process order, lot counts,
and byte-for-byte deterministic generation.

## Repository guide

- `src/fabsight/generators/` contains readable table-generation functions.
- `src/fabsight/validation/` contains relational and timeline checks.
- `scripts/` contains the command-line entry point.
- `data/synthetic/` contains generated CSVs.
- `docs/data_model.md` explains each relationship for beginners.
- `tests/` contains focused pytest coverage for v0.1.

Random `WARNING` and `FAILED` process statuses are independent synthetic workflow
events. They are not caused by tools, maintenance, alarms, or simulated sensors.

## Version v0.2 — SECOM Process Data

v0.2 adds a separate pipeline for the public [UCI SECOM dataset](https://archive.ics.uci.edu/dataset/179/secom).
SECOM provides hundreds of numerical process measurements for each manufacturing
observation and a highly imbalanced pass/fail outcome. It is useful for learning how
to inspect high-dimensional industrial data, handle missing values, and prepare
reproducible train/test files.

SECOM's feature identities are anonymized. A column named `feature_000` means only
the first supplied process variable; it must not be assigned a physical meaning such
as temperature, pressure, a named sensor, or a tool. SECOM also cannot identify the
physical cause of a failed observation.

Prepare the data from the repository root:

```powershell
python scripts/prepare_secom.py
```

The script downloads and caches the official files in `data/raw/secom/`, unless they
already exist. It creates an 80/20 stratified split and writes scaled, imputed data
plus metadata and the fitted preprocessing pipeline to `data/processed/secom/`.
All-missing and constant-column decisions, median values, and scaling parameters are
learned from training data only.

Run the exploratory report:

```powershell
python scripts/analyze_secom.py
```

If downloading is unavailable, both scripts print the official dataset page, exact
filenames, and local destination. The required raw files are `secom.data` and
`secom_labels.data`.

Run all v0.1 and v0.2 tests:

```powershell
python -m pytest
```

The synthetic v0.1 tables and real public v0.2 measurements remain separate. v0.2
does not create fake links between SECOM observations and synthetic wafers, and it
does not train a predictive model. See `docs/secom_overview.md` for the data meaning,
license attribution, preprocessing rationale, and limitations.
